# Корпус языков НИВЦ МГУ

Платформа для морфологического поиска по корпусам малых и исчезающих языков. Сейчас на ней работают корпуса **нивхского** и **караимского** языков.

Сайт: **[corpora.rcc.msu.ru](https://corpora.rcc.msu.ru)**

> **In English.** A multi-corpus search platform for under-resourced languages, developed at the Research Computing Center of Lomonosov Moscow State University. It currently hosts Nivkh and Karaim corpora annotated in Universal Dependencies with Leipzig-style glossing. Each language is described by a single YAML file, so a new corpus can be added without changing Python code. Stack: FastAPI, MongoDB, Jinja2, vanilla JS.

## Возможности

- поиск по словоформам и леммам на языке корпуса и по русскому переводу;
- поиск по грамматическим признакам (часть речи, падеж, время, наклонение, лицо, клитики и др.), до 10 слов в одном запросе;
- глоссирование по Лейпцигским правилам, разметка в формате Universal Dependencies;
- словник с поиском по букве и по лемме;
- виртуальная клавиатура для специальных знаков каждого языка.

## Как устроен проект

Всё, что зависит от конкретного языка, описано в файле `corpora/<id>.yaml`: грамматические категории и их соответствие полям в базе, раскладка формы поиска, клавиатура, алфавитный порядок словника, тексты страниц, стили. При запуске конфиги проверяются Pydantic-моделями, поэтому ошибка в YAML обнаруживается сразу, до первого поискового запроса.

Поисковый запрос сначала переводится в типизированное промежуточное представление (`backend/core/ir.py`), а затем компилируется в aggregation pipeline MongoDB (`backend/db/compile/`). Каждый корпус хранится в своей базе MongoDB.

**Стек:** Python 3.12, FastAPI, Pydantic, MongoDB (Motor), Jinja2, vanilla JS, Fuse.js, Docker Compose.

## Быстрый старт (Docker)

Нужны Docker с Compose и `make`.

```bash
git clone https://github.com/lunadunkel/NivkhCorpus.git
cd NivkhCorpus
cp .env.example .env
make up
```

Сайт откроется на [localhost:8000](http://localhost:8000) (порт задаётся переменной `APP_PORT` в `.env`).

При первом запуске:

1. `data-fetcher` скачивает архив с данными корпусов из [GitHub Release](https://github.com/lunadunkel/NivkhCorpus/releases) в `./data` и готовит JSON к импорту (`docker/preprocess.py`);
2. `mongo` импортирует тексты в отдельную базу для каждого корпуса (`docker/import.sh`);
3. `app` дожидается конца импорта, строит словник для каждого корпуса и запускает сервер.

Первый запуск занимает несколько минут. Повторные запуски используют уже скачанные данные и готовую базу.

### Команды

| Команда        | Что делает                                              |
| -------------- | ------------------------------------------------------- |
| `make up`      | запустить все сервисы                                   |
| `make down`    | остановить сервисы                                      |
| `make restart` | перезапустить                                           |
| `make logs`    | смотреть логи                                           |
| `make build`   | пересобрать образы без кэша                             |
| `make clean`   | остановить и удалить том MongoDB                        |
| `make reset`   | удалить том MongoDB и папку `./data` (полная пересборка) |
| `make help`    | список команд                                           |

## Локальная разработка

Для работы с кодом без пересборки контейнера можно запустить приложение напрямую. Понадобится MongoDB, в которую уже импортированы корпуса: скрипты импорта рассчитаны на Docker, поэтому базу проще всего получить через `make up`.

```bash
python3.12 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

В `.env` укажите адрес базы:

```
MONGO_URI=mongodb://localhost:27017
```

Если словник ещё не построен:

```bash
python -m backend.db.repositories.dictionary -l nivkh -d
```

Запуск сервера с автоперезагрузкой:

```bash
uvicorn backend.main:app --reload
```

## Как добавить новый язык

1. Создайте `corpora/<id>.yaml`. Значение `id` внутри файла должно совпадать с именем файла. За образец удобно взять `corpora/karaim.yaml`.
2. Добавьте стили корпуса в `frontend/static/css/<id>.css` и укажите их в `assets.styles`.
3. Добавьте страницу «О корпусе» в `frontend/templates/about/<id>.html`.
4. Положите размеченные тексты в `data/<id>/`: JSON-файлы с предложениями и `corpus_stats.json` со статистикой.
5. Выполните `make clean && make up`: MongoDB заново импортирует данные всех корпусов. (`make reset` здесь не подойдёт, он удалит и папку `./data`.)

Если в конфиге чего-то не хватает или значения не согласованы между собой, приложение сообщит об этом при старте.
